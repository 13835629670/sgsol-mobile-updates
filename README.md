# 脚本更新（加载器 1 / App 0.4.0）

首次需要安装带加载器的完整 APK。之后到“助手更新”填写本次使用的 GitHub 令牌，点“检查并下载更新”，验签成功后彻底关闭 App 再打开。不会在执行中替换脚本，不改变领取开关。

更新源固定为私有仓库 `13835629670/sgsol-mobile-updates` 的 `latest.json`。每位使用者必须有该仓库的访问权限，令牌只需该仓库 Contents Read 权限。令牌不内置、不写入 localStorage、不进入运行记录，退出进程后消失。仓库私有并不等于 APK 内脚本不可提取。

更新包的 Ed25519 签名覆盖完整 payload（代码、版本、序号、加载器要求）。包大小上限 2,000,000 字符，下载超时 30 秒。公钥固定在 APK，私钥单独保存在工作区外；丢失私钥不能继续给现有安装签发更新。保管私钥备份，不上传仓库。

每次发布递增 sequence，更新包不能超过加载器兼容范围。安装包里的 bundled sequence 必须匹配内置代码，打包前先运行 package-update 生成 config。更新失败保留旧代码；待测版本在下次启动前写入 trial 标记，助手面板就绪且没有已报告错误才确认。两分钟未就绪或中途杀进程，下次启动回退到上个确认版；这只是启动确认，不代表所有业务功能已验证。同步启动抛错时不在同一进程混装两版，需要重开。可以手动选择下次使用内置版；被回退版本不再重复安装，修复后递增序号。

加载器、验签公钥或官方 APK 底层变化仍需要完整 APK 更新。新 APK 内置序号优先于旧下载代码。安装包签名证书与更新签名密钥是两套不同的密钥。

## 发布步骤

1. 修改 mobile 源码、版本，重新提取 core，运行语法检查及 `node --test mobile/test/bootstrap.cjs mobile/test/updater.cjs`。
2. 用 `node mobile/scripts/package-update.cjs <工作区外私钥路径> <输出目录> <递增序号> <版本> 13835629670/sgsol-mobile-updates` 生成签名 `latest.json`。输出目录不能已存在同名包。
3. 核对生成包只含助手代码；先保留上一版，再把签名包发布到私有更新仓库的 `latest.json`。不上传密钥、令牌、账号数据、日志或官方 APK。
4. 下载失败、签名错误、存储不足不影响当前助手。检查签名和启动成功后，再验证目标修复；不以领取奖励作为更新初始化。

构建完整 APK 前必须让 generated/update-config.json 对应 APK 内置的版本和序号；只发布脚本包时无需重建 APK。下载更新不自动执行登录或领取。
